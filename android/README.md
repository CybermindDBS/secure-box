# Secure Box for Android

The Android app is the Secure Box website in a Trusted Web Activity: the app opens the site in
the phone's Chrome, full screen, with no address bar. It's the same code, encryption and security
rules as the website, and every deploy of the website updates the app as well. This folder only
holds the thin wrapper Google Play needs: the app's name, icons, colours, the address it opens,
and its signing.

What only a native app could do (filling passwords into other apps, unlocking with a fingerprint)
isn't part of it.

## Build it

Needs Java 17 or 21 (a JDK, for example [Eclipse Temurin](https://adoptium.net)) and the Android
SDK (installing Android Studio and opening it once sets that up). From the repository's folder:

```powershell
.\android\build-android.ps1
```

- **The first run makes your upload key** in `%USERPROFILE%\.secure-box\upload.keystore` and asks
  you for its password. Back up that file and its password, outside this repository: Google Play
  needs the key for every update. (`-Keystore <path>` keeps it somewhere else.)
- It builds `android\release\secure-box-<version>.aab` for Google Play and
  `android\release\secure-box-<version>.apk` to install on a phone yourself, both signed with your
  upload key, then prints the key's SHA-256 fingerprint and what to do next.
- The password reaches the build tools for that one build only: never on a command line, never in
  a file. A build server can set it in `SECURE_BOX_KEYSTORE_PASSWORD` instead of typing it.
- **Not sure of the password?** `.\android\build-android.ps1 -CheckPassword` builds nothing: you
  type passwords one at a time, and it says whether each one opens the key. If none does and
  nothing has gone to Google Play yet, move the key file away and build again for a new key, then
  publish its fingerprint. Once the app is on Google Play, Play Console can reset a lost upload key
  (under App integrity).

## Let the website vouch for the app

Chrome opens the app full screen only if the site lists it in `/.well-known/assetlinks.json`;
otherwise the app shows an address bar. The deploy script writes and publishes that file, then
checks the live one:

```powershell
.\deploy-firebase.ps1 -AndroidPackage io.github.cyberminddbs.securebox -AndroidFingerprint <upload key SHA-256>
```

Google Play signs the app it delivers with a key of its own. After the first upload, open **App
integrity** in Play Console, copy the SHA-256 fingerprint of the **app signing key certificate**,
and add it the same way (the package name is remembered):

```powershell
.\deploy-firebase.ps1 -AndroidFingerprint <app signing key SHA-256>
```

Both stay listed: the upload key's for the `.apk` you install yourself, Google's for the app from
Google Play. If the app still shows an address bar, `adb logcat` shows why Chrome didn't trust it.

## Publish it on Google Play

1. **A Google Play developer account** (a one-time fee). New personal accounts must run a closed
   test with at least 12 testers, opted in for 14 days in a row, before the app can go to
   production. Organization accounts don't, but need a D-U-N-S number.
2. **Create the app** in Play Console and upload the `.aab` to a testing track. Internal testing
   is the quickest way to get it onto your own phone.
3. **Store listing:** `android\store_icon.png` is the 512 × 512 icon. The privacy policy is
   https://box-6sd93.web.app/privacy.html.
4. **Data safety:** answer from the privacy page. Secure Box has no server and receives no data:
   vaults and files are encrypted on the phone before they reach the person's own Google Drive or
   OneDrive, or a folder on the phone.
5. Each new upload needs a higher `versionCode` in `app\build.gradle`. The website itself never
   needs one: the app always opens the live site.

## What's in this folder

A project generated by [Bubblewrap](https://github.com/GoogleChromeLabs/bubblewrap) 1.27.0
(`twa-manifest.json` records its settings), changed in four ways:

- **No claim on the site's links.** Bubblewrap's app opens every `https://box-6sd93.web.app` link.
  Google and Microsoft send a sign-in back to that address, so on a phone with the app, signing in
  on the website in Chrome would jump into the app halfway and fail. The app opens from its icon.
- **Signing** from `build-android.ps1`, in `app\build.gradle`.
- **Android 7.0 or newer** (`minSdkVersion 24`), what Bubblewrap's own browser helper library
  needs, and Java 11 bytecode.
- **Built with Gradle directly**, with Java 17 or 21: Bubblewrap's own command line insists on
  Java 17 alone.

The app's name, colours and the address it opens are in the `twaManifest` block at the top of
`app\build.gradle`. Regenerating the project with Bubblewrap undoes the changes above, so make them
again afterwards.

## A new web address

The app opens one address, and Chrome trusts it only there. To move the site to a new domain:
change `hostName` in `app\build.gradle` (and `host` in `twa-manifest.json`), raise `versionCode`,
build, deploy the website at the new address with the same `-AndroidPackage` and fingerprints,
then upload the new `.aab`. Cloud vaults are unaffected. Chrome keeps a site's settings per
address, so at the new one it starts afresh: the remembered account, and the folder that holds a
vault on the phone, which is chosen again.
